# Les skills sont livrés dans le worktree, jamais commités

PDO héberge une Banque de skills et livre les skills effectifs d'un NodeRun en les copiant dans `.agents/skills/<name>/` de chaque worktree qu'il crée, avec un lien symbolique par skill dans `.claude/skills/`. Un seul mécanisme pour tous les harnais : c'est le seul emplacement que `claude`, `copilot` et `opencode` lisent sans configuration. Le prix, un fichier posé dans le dépôt cible, est payé par une exclusion Git au grain du skill.

## Options écartées (mesurées le 2026-09-03)

- **Pointeur harnais-natif hors worktree.** `claude` 2.1.258 accepte `--plugin-dir` (testé : un dossier `.claude-plugin/plugin.json` + `skills/` hors dépôt expose bien le skill, préfixé du nom du plugin). `copilot` n'a aucun flag : ses emplacements supplémentaires passent par `skillDirectories` dans son `settings.json` global ou par `COPILOT_HOME`, qui déplace aussi l'authentification. `opencode` remonte depuis le cwd jusqu'à la racine du worktree Git et `OPENCODE_CONFIG_DIR` n'est pas documenté pour les skills. Un trou `{skills}` dans le descripteur (ADR-0045) n'aurait donc été propre que pour `claude` ; l'exigence produit est qu'aucun mécanisme ne soit propre à un harnais.
- **`.agents/skills` seul, sans lien `.claude`.** `claude` 2.1.258 lit `<repo>/.claude/skills/` mais pas `<repo>/.agents/skills/` (testé : même skill, visible dans l'un, invisible dans l'autre). D'où le lien par skill, qui coexiste avec un vrai dossier `.claude/skills` versionné.
- **Laisser le `.gitignore` du dépôt cible faire le travail** (posture d'ADR-0060 pour les chemins runtime). Ici les fichiers sont posés par PDO dans un dépôt qu'il ne possède pas, et un agent peut committer lui-même avec `git add -A` : sans garde, les skills partent dans la PR. PDO écrit donc ses chemins, un par skill et jamais un dossier parent, dans le `info/exclude` du dépôt (partagé par ses worktrees, jamais versionné), les retire au nettoyage du Run, et son commit de complétion les filtre en plus. Un `.agents/skills/` ou `.claude/skills/` versionné n'est jamais ignoré ; un skill homonyme d'un skill versionné est ignoré avec avertissement, pas écrasé.

## Décisions liées

- **Identité par id, nom libellé.** Renommer un skill ne casse aucune référence de tier. Conséquence sur ADR-0059 : le Document de pipeline référence des ids que l'instance réceptrice ne connaît pas, donc l'export embarque le contenu des skills dans un sidecar et l'import les ajoute à la banque. Un skill est du contenu, pas une configuration d'instance ; les profils agentiques restent ramenés à Inherit.
- **Contenu figé au Run, sélection résolue au spawn.** Même partage que le harnais (ADR-0046) et le staging sandbox (ADR-0031) : éditer la banque n'atteint pas un Run en cours ; éditer le YAML atteint les Nodes pas encore lancés. L'instantané du Run est additif pour accueillir un Node dont la sélection a changé après le démarrage.
- **Dossier = geste, pas référence.** Cocher un dossier de la banque coche ses skills du moment. Une référence vivante au dossier aurait recréé le système de références d'ADR-0057 pour un gain que la demande n'exprime pas (« cochés par défaut »).
- **Sandbox et sessions d'infra sans travail dédié.** Le worktree est monté dans le conteneur et les sessions d'infra travaillent dans un worktree ; la livraison in-repo les sert toutes.
