# L'isolation est un choix du Node

Les types `doc-only` et `code-mutating` prétendent décrire l'effet d'un Node alors que leur différence réelle est son répertoire de travail. PDO les remplace par le type `agent`, isolé par défaut dans un sous-worktree. L'auteur peut explicitement le faire travailler dans le worktree partagé du Run. Les Nodes `script` portent le même choix avec le défaut inverse, non isolé. Le Document de pipeline écrit toujours ce choix pour un `agent` ou un `script`, même lorsqu'il égale le défaut. `merge` conserve son isolation imposée, et les Nodes structurels n'en portent aucune. Cette rupture ne porte ni alias, ni migrateur, ni diagnostic propre aux anciens types : les pipelines existants seront migrés manuellement et un ancien type échouera comme toute valeur invalide.

Un Node non isolé peut modifier des fichiers. À sa complétion, PDO stage tout avec la sémantique de `git add -A`, puis commite sur la branche du Run avant de dépêcher l'aval ; aucun changement ne produit aucun commit. PDO n'exclut pas ses propres chemins runtime : le dépôt cible doit les placer dans son `.gitignore` s'il ne veut pas les versionner. PDO reste un outil tranchant : plusieurs Nodes non isolés peuvent s'exécuter en parallèle si l'auteur dessine ainsi son Pipeline, sans sérialisation ajoutée par le runtime. Le premier qui complète commite tous les changements éligibles alors présents sous son propre nom ; l'isolation est le moyen d'obtenir une attribution fiable. Le worktree partagé reste propre à un Run et n'est jamais partagé entre deux Runs de la même Pipeline.

Tous les chemins de complétion passent par la même livraison avant de marquer le NodeRun terminé. Un Node isolé livre ses commits puis merge son sous-worktree ; un Node non isolé commite en place. Le Node ne reçoit aucune consigne Git : il modifie les fichiers, et PDO conserve ses commits éventuels puis crée le commit déterministe `<node-id> iter-<N>: completed` s'il reste des changements. Un échec Git interrompt le Node et garde son travail sur disque. Le diff d'un NodeRun dépend des changements livrés, jamais de son type.
