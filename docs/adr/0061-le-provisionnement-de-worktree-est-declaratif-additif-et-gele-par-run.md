# Le provisionnement de worktree est déclaratif, additif et gelé par Run

Les chemins absents d'un worktree peuvent être provisionnés par des patrons de type `.gitignore`, répartis explicitement entre copie, lien physique et lien symbolique. Les règles se composent de façon additive selon Configuration d'instance → Projet → Run → Node isolé : le niveau le plus précis peut changer le mode ou exclure un patron hérité, tandis que le provisionnement n'écrase ni ne retire jamais un chemin déjà présent. Cette forme garde PDO agnostique des écosystèmes tout en laissant l'utilisateur choisir le compromis entre indépendance, espace disque et partage des écritures.

La recette Instance + Projet + Run est gelée à la création du Run, puis complétée et gelée par itération pour chaque Node isolé ; ses sources restent les chemins courants du dépôt primaire au moment où chaque worktree est physiquement créé. Une réutilisation ne reprovisionne rien et PDO ne déduit aucune invalidation : préserver le travail existant et ne pas inventer la cohérence d'un outil priment sur une remise à niveau implicite.

Les chemins effectivement matérialisés sont enregistrés dans les métadonnées Git propres au worktree et exclus de toute livraison automatique par PDO, même si un Node les a préalablement ajoutés à l'index. Le provisionnement sert notamment à injecter des secrets et des liens vers des ressources locales ; les faire entrer dans la branche du Run contredirait cette frontière et pourrait publier leur contenu ou des chemins absolus de la machine hôte.
