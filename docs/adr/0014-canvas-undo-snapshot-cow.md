# Undo/redo du canvas par snapshots de références — invariant copy-on-write

**L'historique d'undo empile des `PipelineDef` par *référence d'objet*, sans deep clone : toute mutation du store DOIT donc être copy-on-write.** Réaffecter des tableaux/objets entiers (`nodes = [...nodes, n]`, `nodes.map(n => ({ ...n, ...updates }))`) est obligatoire ; muter un objet imbriqué en place (`node.view.x = …`) est interdit. C'est le seul contenu de cet ADR qui compte : l'invariant est **diffus et silencieux** — il ne vit dans aucun fichier, n'apparaît pas au site d'appel de l'undo, et une mutation en place (souvent l'écriture la plus naturelle) **corromprait l'historique sans erreur de compilation ni test rouge évident**.

**Périmètre de l'historique.** Édition pure : il **exclut** l'état runtime (overlay `runState`, ADR-0007) et les **prompts** (édités hors `PipelineDef` ; les couvrir écraserait les éditions de prompt postérieures au dernier push structurel). Annuler un déplacement de nœud ne doit ni ressusciter un état de Run, ni écraser un prompt. Pile in-memory par onglet, non persistée cross-session — l'undo est un filet de séance, pas un journal d'audit (rôle tenu par l'event log). Undo/redo réinitialisent la sélection, dont l'index d'edge est positionnel donc non fiable après coup.

**Écarté : le deep clone par snapshot**, qui supprimerait l'invariant mais coûterait 50 copies d'un `PipelineDef` volumineux. On paie la dette en discipline COW, déjà tenue ailleurs. Un redo qui rejoue une suppression devenue illégale (node passé `running`) est laissé au backstop daemon (409 → SaveError) plutôt qu'à un guard client.
