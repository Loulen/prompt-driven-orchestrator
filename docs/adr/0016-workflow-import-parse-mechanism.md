# Import de workflow — parsing par AST statique, jamais d'exécution du `.js`

**L'importeur ne doit jamais exécuter le JS qu'il importe : il en lit l'AST (`oxc`) et traduit les idiomes reconnus.** Le daemon bind `0.0.0.0` (LAN-reachable, #260) ; exécuter du JS arbitraire d'un fichier importé — même via un sous-process `node` + stubs, mécanique tentante puisqu'elle récupère les prompts *résolus* — y serait une **RCE**, inacceptable pour un simple import. Cette voie ne voit d'ailleurs qu'**un seul** chemin de contrôle (l'exécution réelle) là où l'AST voit **toutes** les branches. Écarté aussi : la **regex**, fragile par construction — un parseur de langage ne se fait pas en regex.

**Extraction des prompts** (le point dur : ils sont souvent construits par des helpers et interpolés à l'exécution). String-literals et template-literals **sans** interpolation → extraits **verbatim**. Template-literal **avec** interpolation → texte statique verbatim, chaque trou `${…}` rendu comme marqueur annoté câblable en port d'entrée. Prompt **sans aucun texte statique** (helper nu, identifiant) → **placeholder annoté**, un nœud `doc-only` dont le corps explique quoi écrire. Tout ce qui sort du sous-ensemble reconnu (boucle imbriquée, garde budgétaire, `try/finally`, accumulation cross-lap) devient un placeholder annoté pédagogique.

## Conséquences

- L'import est une **décompilation AVEC perte** sur un sous-ensemble assumé : la valeur est l'onboarding (« importe le câblage, signale le reste »), pas la fidélité. **L'annotation d'un placeholder *est* le tutoriel** — elle traduit ce qu'un utilisateur PDO n'écrirait jamais à la main (worktrees, auto-cleanup, boucle budgétaire) en interaction délibérée.
- **Aucun nouveau type de nœud** : le placeholder réutilise `doc-only` (inputs émergents → toute edge entrante est valide) ; les avertissements remontent via un canal `warnings` dans le résultat d'import, cohérent avec le lint info-only d'ADR-0001.
- **La reconnaissance de boucle est gardée sur la présence d'un `agent()` dans le corps** : un `while`/`for` de plomberie (double-décodage d'`args`, retry `JSON.parse`) ne matérialise **pas** une boucle — sinon un `bounded` fantôme. Même garde pour `if` → edge conditionnelle.
- **Nouvelle dépendance `oxc`** — lourde mais activement maintenue ; MSRV à vérifier.

**Réutilisé pour l'import d'un nœud YAML unique (#345).** `POST /nodes/parse` applique le même locus *parse-côté-daemon + canal `warnings[]`* à un **nœud nu** (une `LibraryEntry`, pas une pipeline ; disk-free). Différence de nature à ne pas gommer : c'est un round-trip **natif et sans perte** — l'export d'un nœud produit exactement cette forme — pas la décompilation *avec perte* d'un format étranger. D'où le nom produit *Add node from YAML…* et non « import ». Le refus de `for-each` et le défaut-`doc-only` sont partagés via `pipeline::normalize_node_value`, **seule source de vérité de la coercition de type**.
